# 人类规范区

本目录只放**人类手写**的规范、伪代码、不变量和 AI 行为规则。

它的作用不是记录“现在代码怎么写”，而是锁定“应该怎么实现”。项目反复漂移，通常就是 AI 把 `docs/AI/` 里的推导、旧状态或自己的实现当成了需求。

## 优先级

1. **`docs/human/` = 人类意图，最高优先级。**
2. **代码 = 当前事实。** 代码与这里不一致时，视为漂移，不是规范失效。
3. **`docs/AI/` = AI 推导与交接，可能过时。** 不能覆盖人类规范。

发生冲突时：不要让 AI 自行选一个继续写；先记录差异，再按人类规范修代码，或由人类更新规范。

## AI / Agent 规则

- 动代码前先读本目录；有相关规范时，实现必须逐条对照。
- **未经人类明确要求，不要修改 `docs/human/` 下的文件。**
- 不要把自己推断出的“应该是这样”写进本目录；这里只接受人类确认过的内容。
- 实现与规范不一致时，在 PR/issue 里写明：规范条款、当前行为、差异、修复方案。
- `docs/AI/TECH_DEBT_AUDIT.md`、`STATUS.md` 等不能作为需求依据。

## 建议内容

- `AI_RULES.md`：AI 必须遵守的硬规则（禁止项、必做项、验证方式）。
- `ARCHITECTURE.md`：模块边界、依赖方向、数据流。
- `PSEUDOCODE/`：关键算法/流程的人类伪代码，按模块分文件。
- `DRIFT_LOG.md`：已发现的规范与实现差异、处理状态。

新文件可以从 [`SPEC_TEMPLATE.md`](SPEC_TEMPLATE.md) 复制。
