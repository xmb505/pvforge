# 人类确认过的施工图

这里只放**人类确认过**的可实施定义。

“施工图”不是讨论稿、不是 AI 推断、不是代码现状记录，而是可以直接照着实现和验收的规格：

- 术语和数据结构的唯一定义
- 用户操作流程
- 边界、错误、撤销、并发行为
- UI 长什么样、交互怎么走
- 验收条件

## 规则

1. 未确认的草案放在 `docs/AI/`；**确认后才移进本目录**。
2. 每个文件顶部写：状态（已确认）、确认日期、适用模块、确认人。
3. AI 可以起草，但未经人类逐条确认，不得写“已确认”。
4. 与代码冲突时，本目录是目标，代码是现状；先记录漂移，再修代码。
5. 一个主题一个文件，文件名用中文或稳定的英文 slug。
6. 修改已确认的施工图，必须在文件末尾写变更记录。
