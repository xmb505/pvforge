## 3. 合并后的权威需求

> 本节只合并 `role=user` 原文。原文没给的数字/默认值，不写成“用户要求”；确有必要引用现有设计文档的，标 `[文档补充]`。

### 3.1 模型与工程

- 软件基于 Mine-imator 大改，保留 MI 的工作流和术语，做面向 2D PV 的编辑器，让学过 MI 的人能直接画 PV。
- 只服务一个用户；不做旧工程/旧模型兼容；旧 app 只作参考，最终删除并把 `pvforge-next` 改名 `pvforge` `[文档补充]`。
- 新版本必须 **git 友好、AI 友好**：数据拆小、命名稳定、可 diff、可回滚。
- 时间轴上的元素叫**实体**；素材挂在实体上，实体素材可以随时更换。
- 实体至少包含：`start`/`end`、关键帧表（**相对实体**，拖实体时关键帧跟着实体走，不跟主时间线走）、名字（用户可见，可重复，默认取素材名）、UUID（给 AI 看）。
- 任意实体可作父级；子实体坐标/变换跟随父级；用户明确问过摄像机能否当父级/子级，按“可以”实现；文件夹也可参与父子关系。
- 文件夹是“无实物实体”：有坐标、轴心、gizmo；子实体坐标系跟着文件夹走；实体栏显示文件夹树层级，可收起。
- 用户质疑过“场景是什么”，没有要求额外的场景对象层级；当前设计按“无场景对象/场景文件夹”落地 `[文档补充，原文存疑]`。
- 图层顺序：上面的实体应遮挡下面的实体；行是固定槽位，删掉第一行 clip 不能让第二行自动上移；第 3/4 行要能渲染；素材拖到很下面应留在那一行，不能自动回第一行。
- 工程没有固定时长，素材有多长就算多长；没有素材时播放也应像 MI 一样继续，不是 120 帧封顶。
- 首次使用要有欢迎页，引导创建项目（fps/分辨率/背景色等）。
- 标题栏显示保存状态：未保存/已保存；关闭时若有未保存修改要提示保存（已保存不提示）。
- 自动保存可配置，默认 5 分钟一次。
- 退出时保存播放条位置，下次打开工程恢复。

### 3.2 时间轴

- 时间轴秒数栏支持**帧/秒两种显示模式**；帧模式没有“秒”概念，可一直走到几千帧。
- 刻度必须按项目帧率：24FPS 时 0–1s 有 24 格；可渲染成 12/6/4 格，但不能与帧率不符；刻度标注要**正对播放条中心**，不是左对齐。
- Ctrl+滚轮缩放时间轴；Shift+滚轮左右滚动；滚轮上下滚动；横向滚动条不要自动隐藏，要像 Excel 一样留余量；要有竖向滚动条；可以一直拖到“天荒地老”。
- **硬性要求：播放指示条必须永远待在可视时间轴内**；用户往左拖，整个时间轴往左走，往右同理；播放蓝线上的倒三角指针要显示。
- 点中秒数栏后，左右键一次走一帧；长按播放/倒退；不能按一下飞很多帧。
- 点秒数栏可跳转；拖秒数行可 scrub；点关键帧只选中、不跳转；在空白处拖动出现框选框；点其他位置取消选中。
- 提供 clip/关键帧模式切换，避免“怎么区分 clip 和关键帧”的歧义。
- 私有时间线用**悬浮弹层**，浮在 clip 上，不打开新子页面；长度和父 clip 一样，拉伸时一起拉伸；里面不要再塞素材盒，否则无法对齐 clip。
- 私有时间线只保留轨道；左侧素材盒属于主时间轴，不应塞进私有时间线。
- `+` 按钮放在实体/clip 上（用户后来要求放右边、居中），点击出悬浮时间线；若 end 不在窗口内，`+` 渲染在 clip 最靠近时间线窗口边缘处。
- `end` 不在画面内时，子时间线的叉叉/相对按钮放到右边；`end` 不在画面内就放到 start；`start` 不在画面内就强制把时间轴移到有 start 的地方。
- 私有时间线支持**相对/绝对两种模式**；播放轴不在父时间轴范围内就不渲染。
- 子时间轴必须跟父时间轴走；子 clip 长度=父 clip 时，父 clip 的 start/end 仍能正常左右拉；子时间轴对齐问题要修。
- clip 可上下移动；第 7/8 行等深处也要能拖到；空子时间轴只占一行，有一个 clip 就两行。
- clip 可被拦腰斩断成两个；clip 学 PR 做收尾吸附。
- clip 裁剪时，关键帧跟着 clip 走：end 从 5s 拉到 3s 再拉回 5s，4s 的关键帧应被删除，不能“复活”。
- 时间轴旁素材箱做成文件夹样式，可列表/图标、有分类；悬停素材出小浮窗预览；不要把“创建实体/删除”按钮放素材库，素材拖到时间轴就生成预览 clip，删除用 Del 或右键 clip。
- 项目属性的素材箱移到时间线旁边；旧的“帧”素材箱删掉。
- 从工作台创建元素时，start 落在当前播放条位置。
- 视频实体默认长度应等于视频长度，不是默认长度。
- 视频渲染/导出时长跟摄像机存活时间走，不跟全篇走。
- 音频直接上 clip（不要单独波形 tab）；音频实体条画峰值，方便对齐字幕；音频可拖动；“取”按钮应原地裁剪前/后段，不能把音频跳到第 0 帧；逐帧步进时要能听到声音，方便对歌词。
- 导入视频自动拆成视频+音频两个素材，之后互不联动。
- 拖动/缩放实体或 clip 只记一步 undo，不记录中间路径。

### 3.3 关键帧、曲线、求解

- 关键帧帧号相对实体 `start`；拖实体时关键帧跟着实体走；裁剪实体/clip 时越界关键帧删除。
- 关键帧分**普通关键帧**（知道起点和终点）与**求解关键帧**（知道起点，求终点）。
- 曲线/缓动先给函数模板（二次、三次等），用户微调是高级功能；函数直接在关键帧页面选，不单开 tab，不右键选缓动，不做图表/波形 tab。
- 第一帧没有“进入曲线”；曲线属于**到达的关键帧**；要修“0–1 变线性、1–2 变弹跳”的归属错误。
- 选中关键帧后，属性面板显示该关键帧的信息，不是播放条位置的信息。
- 关键帧可拖动、删除、Ctrl+Z 恢复；点选要变色；双击 clip 内部可快速创建关键帧。
- 关键帧位置要校验：不能出现 AI 工作区/文件夹只有 30 帧，却在 90 帧处有关键帧、表面还显示 30 帧的情况；越界要拒绝或明确报错。
- `rotPointX/Y` 必须按“真轴心”语义实现（缩放围绕轴心），不能只是缩放后的平移；或者重命名并在 MCP 文档写清，不能继续用“轴心”误导；vector 建议增加 width 轨道，进度条不必 x+scaleX 双轨。
- 关键帧可加**注释**：人类写“这里是哪个字幕出现位置”等，供 AI 理解（AI 没有耳朵）。

### 3.4 素材

- 素材类型：图片/视频/文字/矢量/HTML/音频/摄像机；图片和视频统一成实体，不是两套对象。
- 右侧素材库与 Mine-imator 一样；素材管理可借鉴 Blender；矢量库要有矩形/三角形/圆形/心形/星形/箭头等大量图标，并提高自定义程度。
- 素材用内容哈希标识/入库（数据库 + 哈希），解决同名不同文件冲突；同 hash 去重。
- “素材 > 全部打包到项目”默认关闭，用户手动开启；开启后自动复制进工程文件夹。
- 素材库“+”按钮可选择所有文件丢进来，由软件识别能否入素材库；导入慢要有等待条，或异步进行并在底部提示栏显示进度。
- 工作台只显示缩略图，实际渲染/导出才上高清原图；视频拖动卡要有后台预览压缩或硬件解码方案。
- 实体可更换素材；更换素材应从素材库选，并显示素材库/预览。
- 素材丢失学 PR：实体保留，工作台渲染“素材丢失”卡片；素材和实体分离；重新导入同 hash 可恢复。
- 文字/矢量作为实体内容参数；不要把它们塞进素材箱（与“时间轴实体、素材在实体上”一致）。
- 视频导入自动拆独立音频素材；音频和视频之后完全不联动。

### 3.5 HTML

- 支持渲染 HTML 页面和前端组件；MCP 可传入 AI 自己写的素材（如进度条）。
- HTML 组件必须暴露 int/自定义变量接口，与时间线联动：工程里可设“第 10 帧=5、第 100 帧=80、二次函数”，由软件控制组件，而不是组件乱跑。
- 三个浏览器进程：前端渲染（低清）/缓存渲染（低清）/成品渲染（高清）。
- 每一帧 HTML 都有画面与缓存；命中直接拿图；未命中前端出图；拖到已缓存帧要秒预览；设关键帧后要立即预取中间帧（示例 101–119）。
- HTML 太重，允许用户自定义 HTML 素材清晰度（设置项）。
- 缓存方案：用户倾向干掉 Redis，改用内置内存缓存 + 自建 LRU，但原文是提问/评估；这是设计结论，不是已验证的用户拍板 `[文档补充]`。看门狗必须异步（这条是用户明确决定）。
- 工作台全局缓存做好后，要评估 HTML 渲染缓存还要不要；不能未经评估直接删，也不能把“保留”写成用户已决定（原文是要求评估）。
- HTML 缓存要按素材/帧/变量值/输出尺寸等区分；不同变量值不能错误命中。

### 3.6 Git、Undo、崩溃恢复

- Git **可选，默认关闭**；全局设置 + 首次进入引导；系统自动找 git 二进制，不手选路径 `[文档补充]`。
- 没有 Git：工程照常创建/打开/保存；只有本次运行的内存 undo；关闭即丢；不能跨会话撤回；**不允许开启 MCP**（原文“没有git也不让开mcp”，不是“MCP 只读”）。
- 有 Git：工程要 git 友好；AI 每次写操作 commit；人类操作按停手 debounce/手动保存合并 commit `[文档补充]`；支持原子回滚、恢复到某个 commit（生成新 commit，不移动 HEAD）`[文档补充]`。
- 内存 undo/redo 不产生 commit、不 `git revert` `[文档补充]`；一次拖动/缩放/属性修改只记一步，不记录拖动路径中间过程。
- 早期“原版没有的跨保存回滚不必做”已被后来的 Git 历史/跨会话恢复需求覆盖：有 Git 时可以跨会话恢复；没有 Git 才不能。
- 崩溃恢复/未提交内容恢复：有 Git 时可用；没有 Git 时不要假装有 `[文档补充]`。
- 自动保存默认 5 分钟，可配置；关闭时提示保存；标题显示未保存/已保存。

### 3.7 MCP

- MCP 必须由人类打开软件后在设置里主动启用；默认关闭。
- 要有明确的 MCP 日志窗口：可放工作区、可新窗口、可关闭；位置应与摄像机监视器一起放视图顶栏（用户明确质疑“为什么丢到视图顶栏里面和摄像机监视器坐一块”）。
- 日志要让人类直观看到 AI 在操作什么：工具、参数、结果、耗时、commit 等 `[文档补充]`。
- 前置辅助是**注释关键帧**：人类在关键帧上写“这里是哪个字幕/干什么”，AI 靠注释理解语义（AI 没有耳朵）。
- AI 必须理解“3D 工作流下的 2D”；场景过去后东西不要了，就用透明度 0%、丢进文件夹、锁上，不要直接删除。
- 必须防止 AI 炸工程：Git 每次写操作 commit、原子回滚；关键帧位置校验；MCP 写操作要串行，不能重入 `[文档补充]`。
- 没有 Git 时不允许开启 MCP（不是“只读”）。
- MCP 必须适配新时间轴/新实体模型；旧时间机制下的 MCP 要全部重新审查；“MCP 是瞎子”的问题要修（AI 看不到关键帧/工作区真实范围）。
- AI 工作区/文件夹的时间范围与关键帧位置要一致；不能只有 30 帧却在 90 帧处藏关键帧。
- MCP 写完成后要刷新 UI（时间轴/视口/属性/素材/工作台），并失效/重扫工作台缓存 `[文档补充]`。
- 危险操作要 `confirm:true`；批量操作要么整批成功要么整批回滚 `[文档补充]`。
- 具体工具数量、端口、token 持久化、错误码等是实现细节，不是用户原话；不要把它们当成用户硬需求。

### 3.8 渲染、导出、摄像机

- 要能渲染出片（MP4）；渲染页要有预览窗口；支持硬件加速/并发；预览显示每秒帧数、预估剩余时间。
- 导出范围按选定摄像机的 `[start,end)`；视频渲染时长跟摄像机存活时间走，不跟全篇走；没有摄像机要报错 `[文档补充]`。
- 导出/预览都要正确处理缺失素材：显示 PR 风格“素材丢失”卡片，不能静默跳过。
- 摄像机是一个矩形：矩形内完全可见，矩形外灰一点；右下角自动出现小监视器，显示最终渲染画面（无辅助线；日常缩略图，高质量预览才用原图）。
- 监视器可拖出成独立窗口，放副屏；工作区本身也算一个摄像机。
- 监视器支持“临摹”：导入参考视频、清除临摹、调描红透明度，用于描改 PV。
- 监视器串流：用户最初明确要求 RTP，手机 VLC 接；后来只反馈 H.265/画质/实时性问题，**没有明确取消**；现有文档写“不做 HTTP/RTP 串流”与原文冲突，需重新确认。
- 摄像机可作为父级（放新闻/台标），也可作为实体子级（跟随镜头）。
- 相机状态栏显示帧率；相机标题栏不能渲染画布外元素。
- 工作台缩略图/低清预览与最终高清渲染分开；视频拖动要流畅（后台预览压缩或硬解）。
- 性能监测模块要做，能看到卡顿来源（如 166s 的 SANY 工程、漫画点阵）。

### 3.9 设置 / UI

### 3.10 工作台缓存

- 目的：长 PV 中前面大量帧已完成、不会改；把这些帧缓存成图片，从头播放全部命中。
- 每帧元信息包含：该帧实际存在的实体、每个实体的坐标/内容/扩展参数、素材是否存在、相机/背景/渲染参数；不在该帧的实体不进元信息。
- 请求第 N 帧：取缓存元信息 → 当前元信息与缓存元信息二进制比较（memcmp/哈希）→ 相同直接取图；不同渲染后写回图+元信息。
- 逻辑要简单：播放头拖到哪帧就查哪帧；miss 渲染，hit 取图。
- **Gizmo 不进缓存**：点击实体只出现 gizmo，实体仍用缓存图；只有 gizmo 实际移动才实时渲染，松手后重新比较。
- 工作台外的实体也必须能看见：设置“工作台扩展缓存机制”，扩展画布外区域缓存；否则缓存命中时用户看不见画布外实体。
- 画布外缓存用**透明底**；相机视图/导出不扩展、不透明。
- 每相机独立缓存；跨会话保留；打开工程后台扫描；播放时暂停扫描；Debug 面板显示总帧/命中/失效/磁盘/预算/扫描进度 `[文档补充]`。
- 默认 50%、宽度上限 1280、磁盘 8GB、内存 256MB 等数字是设计参数，不是用户原话 `[文档补充]`。
- 透明底实测 +20% 体积、以及“用户决定保持透明底”的说法，数据库中没有对应用户消息；用户只说了“透明底，省空间”。要保留透明可以，但不能写成用户已拍板。
- HTML 缓存与工作台缓存的关系：用户要求评估“全局缓存做好后 HTML 缓存还要不要”；现有文档写“保留”是设计结论，不是用户决定。

### 3.11 特殊内容

- 工作台加“特殊”大类，作为一等公民，不用 HTML 重做。
- 漫画文本框至少三类：
  - 普通文本框：可切云朵/矩形/椭圆，都有一个小角可指向一个点，尖尖可自由移动（像 Office）；
  - 日式超绝硬直角矩形：特别尖的直角，不需要三角形；
  - 爆炸文本框：不需要箭头指向。
- 放射状线条：随机抖动、加粗 60%，有手绘感；必须有“随机速度”参数。
- 快速流过：大量线条从一个方向流向另一个方向，让静止的跑步素材看起来在动。
- 漫画点阵：手绘抖动=0 时必须像图片一样完全静止，不能每帧抖动/影响性能。
- 品牌瓷砖墙：像新闻发布会一样平铺 logo；支持多个 logo、改颜色、调间距/密度；按 1 0 1 0 / 0 1 0 1 交替；logo 可用 SVG。
- 文字能力：竖排、日式从右往左竖排、中文竖排从左往右；粗体/斜体/下划线；对话框外层黑边粗细/颜色、内部颜色；行间距/字间距；文字描边；文字不能碰到泡泡边缘。
- 旧 UI 的品牌墙、漫画框等附加功能不能因为删旧 app 丢失。

### 3.12 吸附、Gizmo、缩放

- 选中实体的 gizmo：X/Y 轴 + 圆形旋转线；拖 X 横移、拖 Y 纵移、拖物体自由移动、拖圆环旋转。
- 自定义轴心：启用后 gizmo 绑定轴心，可在画布上移动并吸附实体边缘/四角；关闭后轴心留在原地，gizmo 拖动的是实体，不能回到正中心。
- 移动轴心要重算坐标：视觉位置不变，实体坐标随轴心改变；gizmo 轴心标记用直角，不用十字架。
- 自定义轴心后，实体边缘吸附不能失效；gizmo 要吸附物品边缘和四角。
- 中心吸附：X/Y 到画面中线吸附；整图拖动可吸附画布四角；按 **Ctrl** 临时无视吸附（不是 Alt）。
- 旋转吸附：0/30/45/90 可配；0 默认开，90/180/270 也默认开；特殊角度下实体可吸附画布边缘。
- CAD 手感：两个都处于特殊角（边垂直/平行）的实体可互相吸附边缘；拖拽时生成并渲染延长线，保持方向不变。
- 四角缩放像 PPT：对角固定，上下左右可吸附；可吸附其他特殊旋转实体的四角；边缘中点吸附可在设置打开，默认关闭；会改坐标，用户接受。
- 四角缩放的点点必须跟鼠标，不能漂。
- 锁定实体不能被选中；锁定后不能改关键帧和参数。
- 文件夹要有轴心和 gizmo；多选实体可变成一个文件夹，多选内容可拖进文件夹。
- 吸附阈值、是否允许边缘吸中心线、角度吸附开关都要进设置。
