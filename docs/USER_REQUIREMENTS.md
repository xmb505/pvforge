# 用户需求总表（来自对话，权威）

> 用途：给独立审查 agent 对照项目设计与实现。
> 规则：**同一问题后出现的决定覆盖先前的**；本文与 `ENTITY_MODEL.md` 等设计文档冲突时，以本文为准，并应修正设计文档。
> 来源：`docs/USER_REQUIREMENTS_FROM_DB.md`（原始 `role=user` 消息）与 `docs/USER_DECISIONS_FROM_DB.md`（选择题决策账本）。冲突时以决策账本为准。
> 范围：PVForge 新实体模型（`pvforge-next`），不迁移旧 `.pvproj`。

## 0. 总体原则

- 只服务一个用户；所有回复、issue、文档用简体中文。
- 不要旧工程/旧模型兼容；旧 app 只作参考，最终删除并把 `pvforge-next` 改名 `pvforge`。
- 优先最少代码/标准库/原生方案，不做不需要的抽象。
- 工作区隔离，不同项目记忆不交叉。
- 功能优先正确，再谈性能；所有改动要能构建、测试、端到端验证。
- 用户会午睡/离开；离开期间多派独立 agent 推进，不提问卡住；回来再拍板。

## 1. 实体模型

- 实体有 UUID；名字可重复，默认取素材名。
- `start/end` 是**全局整数帧、半开区间** `[start,end)`。
- `row` 是**每个父级独立**的行号；row 0 在最底，row 越大越靠前。
- 任意实体可当父级；子实体变换是父级局部坐标，继承父级 transform/opacity/可见性。
- 关键帧帧号**相对实体 start**，整数，只在 `0..duration-1`。
- 父实体在时间上移动，后代 `start/end` 同步偏移；父级裁剪级联裁剪/删除后代；扩大范围不恢复已删内容。
- 没有场景对象/场景文件夹/场景写权限；空实体就是无内容实体。
- 全局 markers：不占行、不渲染、不影响时间轴长度。
- 变换公式：`localToWorld(p) = (x,y) + pivot + R·(S·(p−pivot))`；Gizmo、渲染、MCP 共用。
- 摄像机 scale 绝对值限制 0.05..1；其他实体允许负 scale。
- 缺失素材：实体保留，渲染 PR 风格“素材丢失 / MEDIA OFFLINE”卡片（棋盘+红框+短 hash+类型）；视频/HTML“未解码/渲染中”是另一套占位；素材与实体彻底分离。

## 2. 时间轴与编辑

- PR 式从下往上；新实体 row = 整个 `[start,end)` 范围最高占用 row + 1；无限长。
- 私有时间线用**浮层弹窗**；主时间轴双击实体条 = 在双击帧打 key；“+”按钮打开私有时间线。
- 实体第一版**单选**；关键帧支持 Ctrl/Shift 多选、拖动、删除、复制/粘贴（同实体同轨道）。
- 合并菱形：同一帧所有轨道 key 一起移动。
- auto-key 默认开。
- 标记可增删改（标题/颜色/备注/标签/拖动）；标记仍是全局标注，不变成实体。
- 音频实体条画峰值，方便对齐。
- 常用快捷键：Ctrl+E 导出、F 适配、Ctrl+D 原地复制、实体 Ctrl+C/V（时间轴焦点时关键帧复制优先）。
- 视口吸附：像素、画布中心线、其他实体边缘/中点；角度 0/30/45/90，0 与 90/180/270 默认开；**Ctrl 临时关闭**；边缘中点默认关；阈值可设。
- 工作台外的实体（画布外）也要能看见；通过“工作台扩展缓存”解决，扩展区域透明底。
- 多选/框选实体后续再做。

## 3. 关键帧与求解段

- 求解段：一个实体一条时间轴，段不能重叠；一段一个效果（gravity/orbit/spin/blackhole）。
- 开始帧必须是**已有普通关键帧**，人类把它“转换为求解开始帧”，不自动创建 key。
- 结束帧只是停止标记；段内被驱动属性不能有普通 key；段后普通 key 从解算结束位姿继续。
- 裁剪 start 切进段：删段，并把**新起点处的解算位姿**落成普通 key；不能用段起点旧 key。
- 裁剪 end 切进段：结束标记冻结在新末帧；`endFrame=-1` 也要钉住，之后拉长不复活。
- 删除/移动求解段开始 key 必须被拒绝，提示先删段。
- 删除被求解段引用的目标实体前，要返回依赖并要求 confirm 或先改目标。
- 求解段不烘焙；预览和导出使用同一固定步长解算。

## 4. 素材

- 素材没有 UUID，只有 sha256 内容哈希；实体只引用 `assetHash/type`。
- 素材文件在工程 `assets/`，**不进 git**；`.cache/` 也不进 git；不依赖 git-lfs。
- 文本/矢量是实体元数据，不进素材箱；HTML 是 `.pvhtml` 目录包（可 zip 导入）。
- 同 hash 去重，保留第一次导入名；可改名、打标签、搜索/过滤。
- 兼容组：视觉（图/视频/HTML）、生成内容（文字/矢量）、音频、摄像机；空实体可接任意组。
- 换短素材自动裁实体 end，越界 key 删除；音视频不能超过 `sourceIn + 素材时长`。
- 视频导入自动拆独立 WAV 音频实体；之后完全不联动。
- 视频导入后后台按项目 fps 全量抽 WebP 80 图片序列，放 `.cache/video/<hash>/<fps>/<width>/`，像素 hash 去重；LRU 淘汰回退原片；导出用原片。
- 抽图宽度与视频预览代理**共用一个设置**（960/1280），因为抽图就是拿来看的；不另设第二套宽度。
- 打开工程时补抽缺失索引的视频；新导入立即入队；素材箱底部显示 PR 式小进度条/取消。
- 素材丢失/恢复：删除素材不删实体，重新导入同 hash 自动恢复。

## 5. HTML

- 三个 Chrome：前端低清（常驻）、缓存低清（常驻）、成品高清（导出懒启动）。
- 缓存键：assetHash + HTML 本地帧/时间 + 变量值 + 输出尺寸 + Chrome 版本 + bundle 入口 hash；与时间轴位置无关。
- `timeDependent=false` 只缓存一张；true 按帧/变量。
- 低清：工程分辨率比例（25/50/75/100%，默认 50%），宽度上限 1280，WebP 80。
- 缓存：内存 QImage LRU（默认 256MB）+ 本地磁盘 WebP LRU（默认 2GB）；无 Redis/cache-cat/MySQL。
- 预取：当前帧之后到下一个关键帧/变量变化/片段末尾，再向前。
- 当前帧 miss：最多同步等 300ms；超时显示“HTML 渲染中”，后台继续。
- 看门狗：异步 QTimer，只监控播放；每真实上屏一帧喂狗；播放中超过阈值（默认 3000ms 可设）暂停；暂停即睡；手动恢复。
- 成品 finalFrame 支持到 8192px；导出 HTML 4x 大尺寸先确认。
- HTML 缓存的去留：用户要求“评估”，**尚未最终拍板**；当前设计结论是保留（图层级复用、编辑、多相机、导出成品），工作台缓存做好后按命中率缩预算/暂停预取，不能直接删逻辑。
- 播放主时钟是**帧/QTimer**，音频只负责出声，不做主时钟。

## 6. Git / Undo / 崩溃恢复

- **Git 可选，默认关闭**；全局设置 + 首次进入引导；系统自动找 git 二进制，不手选路径。
- 没开 Git 或找不到 git 二进制：工程照常创建/打开/保存；只有本次运行内存 undo，关闭即丢；不 init/commit/读历史/崩溃恢复；**MCP 只读**（写工具 `permission_denied`，reason=git_disabled）。
- 工程有 `.git` 但全局 Git 关闭或无 git 二进制 → 不使用 git。
- 启用 Git：新建时 init；已有工程补 init + 初始 commit；只跟踪 `project.json`、`entities/*.json`、`.gitignore`。
- AI 每次 MCP 写工具调用立即 commit；人类停手 1 秒/手动保存合并 commit。
- 内存 undo/redo：不 `git revert`、不产生 commit；默认最多 200 步或 512MB；素材不进栈；素材标签也不进 undo。
- 打开工程检测未提交文本，弹窗恢复/丢弃/提交为 `pvf: recover`。
- 历史面板可查看 commit 并恢复到任意 commit（生成新 `pvf: restore <hash>` 提交，不移动 HEAD、不 reset）；Git 关闭时面板显示不可用。
- 没有 Git 时不能跨会话撤销；有 Git 时可从历史冷恢复。

## 7. MCP

- 46 个工具（含 asset.setTags）；HTTP loopback；默认端口固定 47821；token 首次生成后持久化；端口冲突明确报错不静默换。
- 默认全工程可写（Git 启用时）；危险操作必须 `confirm:true`。
- 每次写工具一个逻辑操作；批量工具整批成功或整批回滚；纯素材导入可能没有 commit（素材不进 git）。
- AI 写操作期间锁住人类编辑；只读/预览/查询不锁；MCP 日志显示“AI 修改中”。
- 急停：取消当前调用并暂停 AI 写入；已提交 commit 保留；AI 收到“人类按下急停，此次操作未实现”；人类点恢复后继续。
- MCP 日志底部 dock，显示工具/参数/耗时/结果/commit/急停/恢复。
- MCP 写完成后必须刷新 UI（时间轴/视口/属性/素材/工作台），并失效/重扫工作台缓存。
- 人类与 MCP 写入必须串行，不能靠 `processEvents` 重入第二个写事务。
- 没有 Git 时 MCP 只读；`project.get` 的写权限字段要反映真实状态。
- `preview.render_frame` 必须使用编辑器同一套视频/HTML provider，返回文档约定字段；支持 base64/限流。
- `entity.split`（递归切子树、一个 commit）是设计的一部分，不能只写在文档里。
- `entity.move` 只给 row 也要成功；`entity.get` 默认当前播放头且 evaluated 走真实求解。
- 内容兼容：`text/vector -> empty` 必须允许，否则换素材死路。
- `reparent preserveWorld` 对有关键帧的实体不能只改静态 transform；应重算轨道或明确拒绝。
- 缺失素材应出现在 `asset.list/get`，`missing=true`。

## 8. 渲染 / 导出

- fps/分辨率创建后锁定；渲染页可 2x/4x 输出 fps（按时间采样），分辨率 1x/2x/4x；工程数据不变。
- 导出范围 = 选定摄像机 `[start,end)`；没有摄像机报错。
- 4x 输出超过 4096px 先弹确认；8192 上限。
- 音频混音：范围内且**可见**的音频实体，按 start/end + sourceIn + volume 混合 AAC；缺失跳过警告。
- 导出完成后**不自动**打开文件夹；完成弹窗提供“打开文件夹”按钮（用户后来澄清是按钮，不是无条件自动打开）；同名文件先确认覆盖。
- 导出精细控制：CRF 档位、软件/VAAPI 编码器、剩余时间/ETA、导出前预览（后续批次）。
- 素材丢失导出也要显示离线卡片（与预览一致）。

## 9. 设置 / UI

- 功能设置全局（QSettings）：HTML 清晰度/缓存/看门狗/Chrome、视频代理、工作台缓存、MCP 端口/token、Git 开关、人类 commit debounce。
- 工程设置单工程：fps、分辨率、背景色、markers；fps/分辨率锁定，名称/背景色可改。
- 旧 pvforge 深色主题；不做像素风改造。
- 欢迎页最近 10 个项目（名称+路径，双击打开/移除）；路径不存在自动清理。
- 工程属性对话框：名称/分辨率（只读）/fps（只读）/背景色。
- Properties：HTML manifest 变量行（var.* 可打 key）、更换素材+预览、文字排版对话框、33 项缓动（30 预设 + linear/instant/bezier）。
- 相机监视器：可拖出浮窗 + 临摹参考视频；**不做** HTTP/RTP 串流。
- 特殊内容全部保留并作为一等公民 content.kind：漫画框/漫画文字、径向线、流线、点阵、品牌墙；分阶段迁，不用 HTML 重做。
- 旧 UI 附加功能（品牌墙、漫画框等）不能因删旧 app 丢失。

## 10. 工作台缓存（最新架构）

- 每帧完整元信息：该帧实际存在的实体、每个实体的坐标/内容/扩展参数、**素材是否存在**、相机/背景/渲染参数；不在该帧的实体不进元信息。
- 请求第 N 帧：取缓存元信息 → 当前元信息二进制比较（memcmp/哈希）→ 相同取图；不同渲染后写回图+元信息。
- 不做失效区间/脏矩形；元信息天然只受影响该帧的元素影响。
- 整帧场景图（含所有图层/HTML/视频/背景），不含选中框/Gizmo/网格。
- **Gizmo 不进缓存**：点击只出现 Gizmo、实体仍用缓存图；只有 Gizmo 实际移动才实时渲染，松手后重新比较。
- 每相机独立缓存；相机视图不扩展；导出不走工作台缓存。
- 默认 50%（25/50/75/100 可配），宽度上限 1280；磁盘 8GB 可调；内存默认 256MB。
- 跨会话保留，用元信息比较；不整盘清空。
- 打开工程即后台扫描（“上来就生成”）；停止编辑/设置变化后重扫；播放时暂停扫描。
- **画布外扩展缓存**：设置项“向外扩展 %”默认 50%、范围 0–200；只用于编辑器画布视图；缓存世界矩形=画布四周各扩；画布外**透明底**；相机/导出不扩展。
- 透明底实测纯色背景下比填背景大约 +20%，用户决定**保持透明底**，不改成填背景色；以后体积成瓶颈再做 alpha 包围盒裁图。
- Debug 统计面板：总帧/已缓存/命中/失效/磁盘/预算/扫描进度，可重扫/清空。
- 基准：100 实体 5400 帧，元信息构建约 110µs/帧，平均 7.1KB；不同元信息判定 3ns，缓存 miss 查找 26ns，最坏 7KB memcmp 70ns；瓶颈在渲染/解码，不在比较。
- 工作台缓存做好后，HTML 缓存退化为“未命中帧/图层复用”加速层，不直接删除。

## 11. 流程 / 审查

- 多派独立 agent，按目录/模块隔离；不要多个 agent 同时改同一文件。
- 所有 agent 变更必须独立验证、分笔提交，不混半成品。
- 定期做设计一致性审查；发现 P0/P1 先修，不把文档当已完成。
- 工作台/扩展缓存相关文件修改时，审查 agent 要标“进行中”，不能据此判漂移。
