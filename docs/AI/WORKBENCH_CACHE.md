# 工作台缓存（Workbench Cache）

> 目标：3 分钟 PV 做到 2:30 后，前面 2 分钟整帧缓存直接命中，从头播放不再逐层求值/解码。

## 1. 核心思路

- 缓存单位：**一整帧场景图**（含所有图层、图片/视频/HTML、背景；不含选中框/Gizmo/网格）。
- 每帧同时存一份 **帧签名**：该帧实际生效的实体求值结果 + 内容 + 相机/背景 + 渲染参数。
- 播放时计算当前帧签名，与索引里的签名比较：
  - 相同 → 直接读 WebP/QImage，命中；
  - 不同 → 实时渲染，渲染完成后覆盖该帧缓存。
- 不做“失效区间”：签名天然只受真正影响该帧的元素影响。改 2:30 不会改变 1:00 的签名。
- 用户说的“二进制异或”落地为签名字节比较（等价于异或判等），避免碰撞用 SHA-1。

## 2. 帧元信息

每帧存一份**完整元信息**（不是只存哈希），按该帧实际存在的实体记录：

- 渲染器签名：`rendererVersion`、缓存比例、工程宽高/fps/背景色。
- 相机：camera UUID + 该帧求值后的世界变换（无相机时为整画布）。
- 该帧活跃的实体（`start <= frame < end`）及其父链，按 UUID 排序：
  - UUID、parent、row、hidden、visible（含继承结果）、opacity；
  - 求值后的 x/y/rotation/scaleX/scaleY/pivot；
  - 内容：文字全字段、矢量全字段、摄像机、素材（hash/type/sourceIn/volume）；
  - **素材是否存在**（`missing` 标志）；
  - 素材实际源帧：`sourceIn + (frame - start)`（视频/音频）；
  - HTML 变量：`var.*` 轨道在该相对帧的求值 + manifest 默认值；
  - 求解段版本/参数（求值位姿已包含结果，版本用于升级失效）。
- 不包含：实体名字、标签、选中状态、面板状态、音频波形、缓存文件本身。

比较方式：

1. 当前帧按同样规则序列化成确定性二进制（字段顺序固定、浮点原样、实体按 UUID 排序）。
2. 与缓存的元信息逐字节比较（memcmp）；为了加速可先比元信息 SHA-1，再在 Debug/不一致时比原文。
3. 完全一致 → 命中；任一字节不同 → miss，渲染后整份覆盖。
4. 不在该帧的实体完全不进元信息，所以改 2:30 不会让 1:00 失效。

## 3. 存储

每帧存两份数据：

```text
<project>/.cache/workbench/<renderSignature>/<cameraUuid|nocamera>/
    index.sqlite          # frame -> meta blob, image file, bytes, last_access
    <frame>.webp
```

- `renderSignature`：渲染器版本 + 缓存比例 + 工程 fps/宽高 + Chrome 版本（含 HTML 时）。
- 元信息 blob 存在索引里（SQLite BLOB），图存 WebP；比较时先在内存里 memcmp。
- WebP 质量 80；默认比例 **50%**（最大宽度 1280），设置可选 25/50/75/100%。
- 内存 LRU：默认 256MB（已解码 QImage + 最近元信息）；磁盘 LRU：默认 **8GB**，按 `lastAccess` 淘汰。
- 索引原子写；首次访问缓存时加载并清理孤儿文件。
- 跨会话保留；命中某帧时逐个比较元信息，不一致的帧自然 miss 并覆盖，不整盘清空。
- 每相机独立目录；切相机仍命中各自缓存。
- HTML/浏览器低清缓存暂时保留，作为“未命中帧/首次渲染”的加速层；等命中率数据出来再评估是否简化。

## 4. 生成时机（按需，唯一入口是视口）

- **不预热、不后台扫描、不 idle 补帧、不播放前预取。**
- 视口每次实际绘制/请求第 N 帧（`ensureSceneImage` / paint）时：
  1. 构建该帧元信息；
  2. 与缓存元信息逐字节比较；
  3. 一致 → 直接取图；
  4. 不一致/不存在 → `render2` 渲染该帧 → 写回图 + 元信息。
- 第一次走到某帧可能卡一下；之后回头全部命中。
- 打开工程、切相机、编辑、开始播放都不会主动创建扫描任务，也不会提前创建缓存目录；目录在第一次 miss 写帧时创建。
- 只有用户实际看到/经过的帧会进入缓存；不播放、不拖动的等待期间不会新增帧。
- 手动“缓存全部 / 缓存到播放头 / 重新扫描”是可选显式操作，只有用户明确点击才扫描；旧 UI 默认不提供这些菜单入口。播放时暂停手动扫描，停止后从原帧继续。
- **图片命中时仍会构建帧元信息**（签名比较必须做），但元信息里的实体位姿求解走 `EditorSession` 的**会话共享求解缓存**：每个求解段在编辑后（`Document::changed`）预计算一次，之后所有帧、面板和相机复用同一份 `solver::Result`；`anim::Cache::poses` 仍按每次调用临时存在，不会随播放帧数增长。因此“签名命中 → 读图”不再触发整段物理重算。

## 5. 播放命中

- Viewport 实际绘制某帧时先问 `WorkbenchCache::lookup(frame, signature)`：
  - 命中 → 直接贴图；
  - miss → 现有 `render2::renderFrame` 实时渲染，再同步写入缓存。
- 摄像机监视器仍然独立渲染（不改变画面/裁剪），但同样借用会话共享求解缓存，重复重绘同一帧不会重复解算物理段。
- 只有真正绘制过的帧参与命中/失效计数；未访问的帧不影响统计。
- 命中/未命中计数、当前手动扫描帧、磁盘占用写入 Debug 面板。
- 音频仍实时播放；缓存只影响画面。
- 导出不强制走工作台缓存（导出用原片/高清 finalFrame）。

## 6. Debug 页面

`视图 → 工作台缓存…` 打开非模态统计面板：

- 开关状态、比例、相机、渲染签名；
- 总帧数 / 已缓存 / 签名命中 / 签名失效 / 本次运行命中率；
- 磁盘占用 / 预算、内存帧数；
- 手动扫描进度/当前帧：默认空闲；只有用户点击“重新扫描”时显示。
- “重新扫描”“清空缓存”按钮。

## 7. 明确不做

- 不做分层缓存（每实体一层、局部重合成）。
- 不做失效区间/脏矩形。
- 不缓存音频波形/频谱。
- 不把工作台缓存当导出成品源；导出仍按 9 节流程。

## 8. HTML 缓存去留评估

工作台缓存与 HTML 缓存不是同一层：

- 工作台：整帧、按相机、按最终画面；命中后完全不需要 HTML。
- HTML：单个素材的内容图，键为 `assetHash + 本地帧/时间 + 变量 + 尺寸 + Chrome 版本 + 入口 hash`。

HTML 缓存仍有价值的场景：

| 场景 | 无 HTML 缓存 | 有 HTML 缓存 |
|---|---|---|
| 静态 HTML 铺满 3 分钟 | 按需/手动渲染 5400 帧要渲染 5400 次相同页面 | 渲染 1 次，5400 帧复用 |
| 移动/缩放 HTML 图层 | 工作台元信息变 → miss，但 HTML 内容没变 | 重合成时 HTML 图直接命中 |
| 多相机 | 每个相机重复渲染同内容 | HTML 图跨相机共享 |
| 编辑 HTML 变量 | 每次重新渲染 | 只渲染变量/帧变化组合 |
| 导出高清 | 工作台 50% 图不能用 | 成品浏览器按最终分辨率渲染（本来就不缓存） |

推荐：

1. 保留 HTML 前端 + HTML 缓存，但磁盘预算从 2GB 降到 512MB～1GB（可设置）。
2. 播放纯缓存区间时暂停 HTML 缓存浏览器预取；miss/编辑时唤醒。前端浏览器常驻。
3. 成品浏览器永远保留，导出必须走 finalFrame。
4. Debug 面板采集：工作台命中率、HTML 内存/磁盘命中率、手动扫描 1 分钟耗时（开/关 HTML 磁盘缓存）。
5. 判定线：HTML 磁盘命中率 <5% 且工作台命中率 >95% → 可关 HTML 磁盘缓存，只留 256MB 内存；否则保留并缩预算。HTML 的变量/帧缓存逻辑不删。

## 9. 基准（2026-11-10）

环境：Release、100 个实体、5400 帧、1920×1080@30、50% 缓存（960×540）。

| 指标 | 结果 |
|---|---:|
| 元信息构建 | 113.7 µs/帧 |
| 元信息平均大小 | 7.1 KB/帧 |
| 缓存命中查找 | 14.0 µs（含索引/内存取图） |
| 5400 帧元信息常驻内存 | 约 38 MB |
| 帧预算占比（30fps） | 0.34% |
| 不同元信息判定（SHA-1 首字节不同） | 3.1 ns |
| 缓存 miss 查找（索引 + 比较） | 25.9 ns |
| 446 B 元信息最后 1 字节不同 | 7.7 ns |
| 7112 B 元信息最后 1 字节不同（最坏 memcmp） | 69.6 ns |

结论：不同元信息判定是纳秒级，最坏 7 KB memcmp 也只有约 70 ns；瓶颈在元信息构建（约 110 µs/帧）、WebP 解码和渲染，不在比较。后续如需再优化，优先做图片内存预取，而不是哈希/比较。

### 9.1 实机冒烟（640×360 工程）

测试工程：7 实体（摄像机/文字/矢量/图片/视频/音频/HTML），60 帧@30fps，50% 缓存（320×180）。

- 显式执行一次“缓存全部”后预渲染 **60/60 帧**，耗时约 **1.4 秒**，磁盘 **1.1 MB**。
- 正常打开工程不扫描；首次播放/拖动只写实际经过的帧，回头命中。
- 关闭应用重开：已写过的帧元信息命中，WebP 文件 mtime 不变，不再重新渲染。
- 简单矢量/文字工程的按需渲染速度远快于实时；HTML/视频重的工程取决于首次 HTML/解码成本。

## 10. 画布外扩展缓存

人类需求：光标移到画布外/缩放平移时，缓存命中也不能看不见画布外实体。

- 设置项：`工作台缓存向外扩展 %`，默认 **50%**，范围 0–200。
- 只作用于**编辑器画布视图**（`cameraUuid` 为空）：
  - 缓存世界矩形 = 画布四周各扩 `宽 × expand%`、`高 × expand%`；
  - 视口按该世界矩形绘制，画布外实体正常显示；
  - 相机视图不扩展，导出仍用相机/原片。
- 缓存元信息与目录签名包含 `expandPercent`；改设置会自然 miss 并重建。
- **画布外透明底**：扩展缓存图先填透明，只在画布矩形内填项目背景色；画布外实体画在透明底上。WebP 支持 alpha，透明区域压缩后体积很小。
- 视口绘制透明缓存图时，透明区域直接露出视口背景，不额外填色。
- 相机视图/导出仍整张填背景，不使用透明底。
- 缓存尺寸 = 扩展后世界矩形 × 分辨率比例，宽度仍受 maxWidth 限制。
- 代价：50% 扩展时面积 4 倍；预渲染时间同比增加。
- 实测：500×500、200% 扩展、纯色背景下，透明底 WebP **832 B**，整张填背景 **694 B**，透明底约 **+20%**。原因：WebP 对纯色压缩几乎免费，alpha 有固定开销。人类决定**保持透明底**（正确性/视口叠图优先），不改成填背景色；若以后体积成为瓶颈，再做 alpha 包围盒裁图。
