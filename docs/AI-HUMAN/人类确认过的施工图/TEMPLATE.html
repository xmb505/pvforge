1目标

这个模块 / 功能到底解决什么问题。只写用户能感知的结果，不写实现方案。

2非目标

  • 明确不做什么，防止 AI 扩展范围。
  • 明确本版不兼容的旧行为。

3术语

4数据结构

StructName {
    field: Type   // 含义、单位、约束
}

字段必须写清：单位（帧 / 像素 / 百分比）、默认值、合法范围、是否可为空、序列化名称。

5用户流程 / 伪代码

1. 用户...
2. 系统...
3. 结果...

先写人的动作，再写系统反应；不要先写类名和函数名。

6UI 与交互

UI 施工图必须是 HTML；静态截图只能作为附件，不能替代可点击的 HTML。

7边界与错误

  • 空、零、负数、越界。
  • 撤销 / 重做。
  • 并发 / 取消 / 关闭。
  • 数据损坏 / 版本不匹配。
  • 错误码与用户可见文案。

8不变量

  • 任何时刻都必须成立的条件。
  • 违反时是崩溃、拒绝操作，还是自动修复。

9验收

  • 可执行的测试名 / CTest 名称。
  • 可观察的行为。
  • 失败时用户看到什么。
