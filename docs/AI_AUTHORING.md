# PVForge AI 作者指南

> 面向通过 MCP 操作 PVForge 的大模型。本文讲工作流、坐标、场景边界和安全规则；HTML 组件的完整契约见 [M6_HTML_API.md](M6_HTML_API.md)，方案与阶段拆分见 [M6_PLAN.md](M6_PLAN.md)。
>
> 状态：M6 文档草案。工具名与错误码按 M6 计划书写；实现落地时以 `tools/list`、`guide.get` 和实际错误消息为准。拿不准就停下问人类，不要猜。

## 0. 一句话

PVForge 是 Mine-imator 式工作流（对象树 + 时间轴 + 关键帧 + 相机）的 **2D** 版本：所有内容都是画布上的图层，没有 3D 场景、没有 z 轴、没有 Minecraft 资产。你通过 MCP 读写一个已经打开的工程，人类始终在旁边看着，并且可以随时急停。

## 1. 心智模型

### 1.1 画布坐标

- 单位是**像素**，不是米、不是归一化坐标。
- 原点是**画布中心**，x 向右为正，**y 向下为正**。
- 1920×1080 工程：左上角是 `(-960, -540)`，右下角是 `(960, 540)`。
- 实体的 `position` 是**轴心**的位置，不是左上角。默认轴心在图层中心，所以把 800×120 的 HTML 层放在 `(0, 360)`，它的范围是 x `-400..400`、y `300..420`。
- 旋转单位是度；因为 y 向下，屏幕上的正值是顺时针。
- 缩放是倍数，`1` = 100%。子级的缩放会与父级链相乘。
- 没有 z 轴、没有景深、没有透视。前后关系只由时间轴行顺序决定。

### 1.2 时间轴、clip 与私有时间线

- 时间轴上的每个实体是一个 **clip**；`clipStart` 是起始帧，`clipEnd` 是结束帧（左闭右开）。`clipEnd` 缺省或 `clipEnd <= clipStart` 表示开放结尾；读取时看 `clipOpen`。
- 时间轴行是稳定槽位，不是自动压缩的列表：删掉第 0 行的 clip 会留下空行，第 1/2 行不会上移。行号在 `row`（持久化字段是 `data.timelineRow`）；`row = -1` 表示尚未分配。
- `parent` 同时是**私有时间线 owner**：子实体只在父 clip 的私有时间轴里显示，主时间轴不列子实体。主时间轴根层是 `parent = -1`。
- 创建子 clip：`entity.create` 传 `parent = owner 实体 id`，并在 `data` 里给 `clipStart/clipEnd/timelineRow`。owner 可以是任意非音频实体；音频不能当父级。
- 改 clip 范围或行：`entity.update` 的 `data.clipStart/clipEnd/timelineRow`；`entity.move` 支持 `row` 参数，换父级会清掉旧行号。
- 时间轴最上面一行 = 画面最前；图层顺序按行号排序。新实体没有指定行时追加到底部。
- 文件夹是只有变换、不参与绘制的实体；文件夹的移动/旋转/缩放会带动整棵子树。
- 隐藏、锁定、透明度沿父级链生效；有效透明度为 0 的子树视为不存在（不渲染、不参与点击、视频不解码）。
- 父级链最多 64 层，禁止循环。摄像机可以作为父级，让台标/字幕条固定在镜头画面里；摄像机不能以另一个摄像机为父级。
- 默认把新实体放进**当前场景的根文件夹**，除非你明确需要别的父级/私有时间线。

### 1.3 关键帧与缓动

- 每个属性一条 `Track`，关键帧落在整帧上；两个关键帧之间按缓动插值。
- **缓动属于“到达的关键帧”**：给 24 帧处的关键帧设曲线，影响的是 0→24 帧这一段；0 帧没有进入段，给 0 帧设曲线没有意义。
- 第一帧之前保持第一帧的值，最后一帧之后保持最后一帧的值；只有一个关键帧时全程恒定。
- 线性：匀速。
- 瞬间（Instant）：保持前一个值，到关键帧的瞬间跳变。
- 预设：缓入/缓出/缓入缓出 × quad/cubic/quart/quint/sine/expo/circ/elastic/back/bounce。
- 自定义贝塞尔：两个控制手柄，P0 `(0,0)`、P3 `(1,1)`；x 会被夹在 `[0,1]`，y 允许过冲（回弹类效果）。
- 用 `easing.set` 改的是**目标关键帧**，不是出发关键帧。想让 0→72 帧匀速，就把 72 帧的缓动设为线性；想让它结尾减速，就改 72 帧的缓出。

### 1.4 摄像机

- 相机是画布内的一个 **2D 取景框**，不是 3D 相机：位置、取景比例（5%–100%）、旋转、关键帧。
- 没有 z 轴、没有 FOV、没有焦距、没有景深。
- 活动摄像机决定监视器和导出看到的画面；`project.summary` 会返回当前活动摄像机。
- 取景框外是黑色；未旋转的框限制在画布内，旋转可以越界。
- 摄像机可以作为父级，让图层固定在镜头画面内；摄像机也可以挂到文件夹/实体下跟随移动，但不能再挂到另一个摄像机下。
- 不要为了“推近”去改工程分辨率或缩放整个场景；用摄像机的取景比例。

### 1.5 场景

- 场景是一等公民：`id`、名称、起始帧、结束帧、根文件夹、颜色、备注。
- 场景**不重叠**，按起始帧排序；中间允许留空。
- 当前播放头所在的场景就是你的写入范围。你只能写**当前场景根文件夹**里的实体，以及人类显式解锁的全局对象（活动摄像机、音频、全局台标等）。
- 新实体默认落在当前场景根文件夹；不要写到别的场景，也不要移动场景边界。
- `scene.create` 只能追加到时间轴末尾，且不能与现有场景重叠。恢复退休场景只能由人类做。
- 播放头落在场景之间的空隙时，没有当前场景；此时不要写入，报告人类把播放头移到场景内。

### 1.6 退休：永不删除

- **没有任何删除实体的工具，删除是永久禁止的。** 不要试图用“清空关键帧”“移到看不见的地方”“改名为空”来模拟删除。
- 不需要的内容用 `entities.retire` 退休：
  1. 透明度设为 0；
  2. 移入名为 `_retired/<场景名>` 的文件夹（没有就创建）；
  3. 锁定。
- 退休保留数据、关键帧和注释，人类以后可以恢复；AI 不能恢复退休内容。
- 退休后的实体不渲染、不参与点击，视频也不解码。
- 不要往 `_retired` 里新建内容，也不要把退休文件夹当作正常图层组。

### 1.7 注释与音频摘要：AI 没有耳朵

- 全局标记轨：帧号、标题、Markdown、标签（字幕/场景/副歌/镜头）、颜色。
- 关键帧备注：挂在关键帧上的文字备注，不参与渲染。
- 注释由人类写，AI **只读**；没有写注释的工具。
- AI 不能听音频，也没有 BPM 分析。开始做卡点/字幕/副歌动画前，必须先读：
  - `annotations.list`：这一帧发生了什么、哪一段是副歌；
  - `scene.context`：场景区间和场景备注；
  - `audio.summary`：音频时长、开始/裁剪、波形峰值摘要。
- 注释里可能写着“这里进副歌”“第 48 帧鼓点”“字幕从 12 帧开始”。把这些当作创作方向；没有注释就不要声称“卡上了节拍”，按场景边界或保守的匀速处理，并在报告里说明。

## 2. MCP 工作循环

固定顺序：**先读上下文 → 再写 → `preview.render_frame` 自查 → 失败就停**。

### 2.1 先读

至少读这些，再动手：

| 工具 | 你要确认的事 |
|---|---|
| `project.summary` | 分辨率、帧率、时长、活动摄像机、场景列表 |
| `scene.list` / `scene.context` | 当前场景、根文件夹、帧区间、注释、实体 |
| `annotations.list` | 全局标记、关键帧备注、歌词/鼓点提示 |
| `audio.summary` | 音频时长、裁剪、峰值摘要 |
| `timeline.get` / `entity.get` | 已有实体、clip 范围/行、轨道、关键帧，避免撞帧/覆盖 |
| `assets.list` / `html.get` | 可用素材、HTML 变量 schema |
| `guide.get` | 本指南、HTML 契约、示例 |
| `preview.render_frame` | 改动前的基线画面 |

特别注意：

- 先看**当前场景**，不要假设工程只有一个场景。
- 先看**已有轨道**，不要用同名实体或同帧关键帧覆盖人类的工作。
- 先看 **HTML 资产变量**，不要凭资产名字猜变量。
- 需要卡点时，先读注释和音频摘要；读不到就停下来问。

### 2.2 再写

- 只在“允许修改”模式下写；默认只读。
- 只写当前场景根文件夹 + 人类显式解锁的全局对象。
- 一次语义完整的修改放进一个 `batch.run`：整批原子提交，一条撤销，一个 checkpoint。单批最多 200 个操作。
- 优先用 `entity.update`、`keyframes.set`、`easing.set`、`variables.set_keyframes` 这类语义工具，不要拆成大量单属性调用。
- 实体命名要能让人看懂（例如“进度条”“副歌歌词”），不要用随机字符串。
- 不导出 MP4，不改工程设置，不开关 MCP，不写注释，不碰文件路径，不执行命令。
- 活动摄像机、音频、全局台标属于全局对象；没有明确解锁就不要改。

### 2.3 自查

写完必须用 `preview.render_frame` 看结果，至少检查：

- 起始帧、关键中间帧、结束帧；
- 图层确实出现，位置/大小/透明度正确；
- 没有占位框、黑底、空白、文字裁切；
- 变量驱动的画面（进度条、字幕条、卡拉 OK）在中间帧处于预期状态；
- 返回的场景摘要里没有多出/少掉不该有的实体。

`preview.render_frame` 服务端限流约 2 次/秒；不要连续狂刷。检查 3–5 个关键帧通常足够。

### 2.4 失败就停

- 任何 `render_timeout` / `render_failed` / 占位框 / 与预期明显不符，都视为自查失败。
- 失败后**停止当前任务**，不要再叠加修改，不要“再试一次看看”。
- 报告：失败帧、工具名、实体/场景、错误码、你看到的画面、你最后成功的一步。
- 参数类错误（缺字段、类型不对）可以在**未产生写入**的前提下修正一次；权限、急停、渲染失败不重试。

## 3. 权限、急停、限额

### 3.1 权限

- 默认只读；人类在设置或日志窗点“允许修改”并确认后才可写。
- 只读模式下调用写工具返回 `permission_denied`；不要换工具绕过。
- 越出当前场景根文件夹、改全局对象/设置/注释，同样返回 `permission_denied`。
- `permission_denied` 的正确反应：停止写入，告诉人类当前场景和需要解锁的范围。

### 3.2 急停

人类可以按红色“停止 AI”、视口浮动红标或全局快捷键急停。行为：

1. 中止当前工具调用和浏览器抓帧；
2. 清空排队；
3. 恢复本批次开始时的快照；
4. 当前调用返回 `stopped_by_human`；
5. 服务端进入“已急停”，所有写操作拒绝，读操作保留；
6. 人类重新点“允许 AI 操作”后才恢复。

收到 `stopped_by_human` 后：

- **立即停止，不重试，不换工具，不拆小批次绕过。**
- 不要继续发写请求；可以等人类重新授权后再从读取上下文开始。
- 不要假设你的上一批修改还在——批次已经回滚。

### 3.3 限额

- 单批 ≤ 200 个操作；
- 工程实体 ≤ 5000；
- `preview.render_frame` ≤ 2 次/秒；
- 单个 blob ≤ 5MB；
- HTML：单层 HTML ≤ 2MB，单资产 ≤ 5MB，单层组件 ≤ 16，同时 ≤ 4 个 HTML 层，抓帧边长 ≤ 4096，每层最多 1 个在途抓帧。

超过限额会返回 `limit_exceeded`。缩小批次/范围一次；仍然超限就停，不要反复试探。

### 3.4 错误码与反应

| 错误码 | 含义 | AI 该做什么 |
|---|---|---|
| `permission_denied` | 只读、越出当前场景、改全局对象/设置/注释 | 停止写入，报告当前场景与需要解锁的范围；不重试 |
| `stopped_by_human` | 人类急停，批次已回滚 | 立即停止全部调用；不重试、不绕过；等人类重新授权 |
| `conflict` | 你读过的实体/关键帧/场景已被人类改过 | 重新读一次上下文；仍冲突就停，不要覆盖 |
| `limit_exceeded` | 批次、实体数、截图、blob 或 HTML 限额 | 缩小批次/范围一次；仍超就停 |
| `render_timeout` | HTML 组件在超时内没有完成本帧 | 停止；报告帧号和层；不要连续抓帧重试 |
| `render_failed` | HTML 组件 JS 异常、浏览器崩溃或抓帧失败 | 停止；报告错误；不要导出或继续写 |
| `browser_unavailable` | 找不到可用的 Chrome/Edge | 停止 HTML 层的创建/渲染；报告人类安装浏览器 |
| `invalid_asset` | HTML 资产格式/manifest 不合法 | 修正资产后重新导入一次；不要反复导入同一份坏资产 |
| `invalid_argument` | 参数缺字段/类型错误 | 修正参数一次；不要循环调用 |

实现阶段可能还有更细的错误码；以实际返回为准。原则不变：**权限/急停/渲染失败不重试，参数错误最多修正一次。**

## 4. HTML 组件

HTML 组件是“只读素材”，不是可以随手改的代码文件：

- 一个资产 = 一个完整 HTML 文档 + manifest，存在单个 JSON 里；宿主不拼接 HTML 片段。
- 组件只能用 `pvf` API 读取当前帧；画面必须由变量/帧/时间决定。
- 变量只支持 number（double）；文本内容固定在 HTML 里，变量控制进度、位移、透明度、显隐等数值。
- 变量轨道命名是 `var.<组件 id>.<变量名>`；属性面板显示为 `组件名.变量名`。
- 换素材时按变量名匹配保留关键帧；新变量用默认值；旧变量轨保留但标记未使用。

### 4.1 确定性

组件必须是纯函数：

- 同一帧连续渲染两次，像素必须一致；导出同一帧两次也必须一致。
- 禁止 CSS animation/transition、自由 `requestAnimationFrame` 动画；每一帧只由宿主调用 `pvf.render`。
- 禁止 `Date.now`、`performance.now`、`new Date()`、`Math.random()`；宿主虽然会固定时钟/种子，但不要依赖。
- 字体/图片/ SVG 必须内联（data URL）或走工程内资产；不能联网、不能读本地文件、不能播放媒体。
- 禁止 WebGL、视频、音频、iframe、Web Worker、fetch/XHR/WebSocket、外部脚本/样式。
- 使用 Canvas 2D 时，每帧同步重绘；图片必须在 `pvf.ready()` 之前加载/解码完成。
- 如果组件读取 `pvf.frame` / `pvf.time`，manifest 必须声明 `timeDependent: true`；否则宿主可能按变量缓存帧。

### 4.2 尺寸与限额

- `manifest.size` 是逻辑像素尺寸，也是抓帧比例；不要用 `window.innerWidth` 猜。
- 单层 HTML ≤ 2MB，单资产 ≤ 5MB，单层组件 ≤ 16，同时 ≤ 4 个 HTML 层，抓帧边长 ≤ 4096。
- 默认单帧渲染超时 1 秒；超时视为失败，预览显示占位并记日志，导出直接报错，不输出错帧。

### 4.3 示例

可直接导入的示例在 [`examples/html/`](../examples/html/)：

- `progress-bar.json`：进度条，变量 `progress.value` 0–100；
- `lower-third.json`：人名条，文本固定，变量 `lowerthird.enter` / `lowerthird.accent` 控制入场与强调线；
- `karaoke.json`：卡拉 OK 高亮，变量 `lyrics.progress` 0–100，用 CSS clip 高亮。

写新组件前先读 [M6_HTML_API.md](M6_HTML_API.md) 的完整契约；不要发明未定义的 API。

## 5. 完整示例：做一段 3 秒进度条动画

假设：工程 1920×1080、24 fps，当前场景 `S1` 覆盖第 0–72 帧，音频从第 0 帧开始。3 秒 = 72 帧（0 到 72）。如果帧率不同，先按 `project.summary` 重算，不要硬编码。

### 第一步：读

1. `project.summary`：确认 1920×1080、24 fps、活动摄像机、场景列表。
2. `scene.context`：确认当前播放头在 `S1`，拿到根文件夹 id 和场景区间 0–72。
3. `annotations.list`：看 0–72 帧有没有“进度条从这里开始/这里结束”的标记；有就按标记调整。
4. `audio.summary`：确认音频没有裁剪/延迟，3 秒对应 72 帧；如果音频开始帧不是 0，按实际起点平移。
5. `assets.list` / `html.get`：看进度条资产是否已存在；存在就直接复用，不存在再导入。
6. `preview.render_frame` 看第 0 帧基线：确认场景里已有内容、没有占位框。

### 第二步：导入资产（仅当资产不存在）

7. 用 `assets.import_blob` 导入 `examples/html/progress-bar.json` 的 base64，元数据名称“进度条”，类型 HTML；不要传文件路径。
8. 读返回的资产 id 和变量 schema，确认组件 id 是 `progress`、变量是 `value`、范围 0–100、默认 0。

### 第三步：建层

9. `html.create_layer`：资产 id 用上一步的返回值，名称“进度条”，父级为 `S1` 根文件夹，位置 `(0, 360)`，使用资产逻辑尺寸 800×120，不透明。
10. 确认新层落在 `S1` 根文件夹内，且没有跑到别的场景。

### 第四步：打变量关键帧

11. `variables.set_keyframes`：目标实体是新层，轨道 `var.progress.value`。
    - 第 0 帧：`0`
    - 第 72 帧：`100`
12. 缓动：给**第 72 帧**设线性（默认就是线性）；这样 0→72 帧匀速。想要结尾减速，就改第 72 帧为缓出，不要改第 0 帧。
13. 用 `timeline.get` 复核：两个关键帧都在，帧号和值正确，轨道名没有拼错。

### 第五步：自查

14. `preview.render_frame` 抓第 0、36、72 帧（间隔调用，遵守 2 次/秒）：
    - 第 0 帧：填充 0%，文字 `0%`；
    - 第 36 帧：约 50%；
    - 第 72 帧：100%；
    - 三帧都没有占位框、黑底、文字裁切，进度条在画面下方居中。
15. 如果中间帧不是约 50%，先停：可能是帧率不是 24、关键帧打错轨道、或资产变量名不对。报告具体现象，不要继续加动画。

### 第六步：报告

16. 报告实体 id、资产 id、场景、关键帧（0→0、72→100）、缓动、检查过的帧。
17. 如果任何一步失败：停止，不追加新实体，不重试急停/权限/渲染失败，把错误码和最后成功步骤交给人类。

> 这个例子只用了一个 HTML 层和一个变量。真实任务里如果还要加标题、背景、歌词，继续用 `batch.run` 在当前场景根文件夹内追加；不要跨场景，不要删除旧内容，不要改活动摄像机（除非人类明确解锁）。
