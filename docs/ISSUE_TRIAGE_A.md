## 重点说明

### #5 要按新资产模型重写

新模型里素材没有“模板/实例”的强弱关系：实体只引用内容哈希，删除仍被引用的素材不会阻止，实体显示“素材缺失”，重新导入相同内容自动恢复。

原文的“只删模板 / 同时删实例 / 取消”三选一已经过期。重写方向：

- 标题改成“素材库缺少删除素材入口”；
- 删除对象是资产库条目，不是时间轴片段；
- 引用中的资产可以给提示，但不阻止删除；
- 删除后时间轴显示缺失占位，重新导入即恢复。

### #10 保留结论，删掉回退分支

“导出范围=选定摄像机区间”已经是新模型的正式行为，这部分不用再讨论。需要改的是原文最后一条：没有摄像机时不是回退全篇，而是直接报错，提示先创建/选择摄像机。

重写时补两个待定项：

- 导出文件从 0 开始，还是保留全局帧号、只导出该区间；
- 预览、导出、MCP 返回的时长字段必须用同一套规则，避免界面和文件时长对不上。

### #14 切分的数据表示问题已经解决

新模型允许同一行放多个互不重叠的实体，按 start 排序。切分不再需要“一行多段”的特殊结构，直接做成：

- 复制实体，左段 end=播放头，右段 start=播放头；
- 关键帧按裁剪规则处理，切点两侧各自保留；
- 子实体按范围分配、两侧复制还是拒绝切分，需要拍板；
- 整个切分是一个操作、一个 commit、一次 undo。

### #16 HTML 已资产化，不能再按实体类型创建

HTML 不再是独立实体类型，而是资产类型。MCP 的正确工作流是：先导入 .pvhtml 资产，再创建 asset 内容槽实体或把资产指派给已有实体。

重写方向：标题改成“MCP 创建 HTML 实体需先导入 .pvhtml 资产”；错误信息要指路，而不是“未知实体类型”。如果产品要求一步创建，需要单独拍板是否允许工具内部代导入。

### #9 和 #19 不是重复

#19 是变换语义问题，属于模型层，新模型 3.5 已经给出 MI 语义，可以关闭。
#9 是手柄交互问题，属于 gizmo 层；3.6 给了期望行为，但旧实现里的跟手/跳变是否彻底消失，要看新模块实测，所以留待验证。

### D 类关闭前要登记验收

新模型目前是设计文档，并行模块还在实现。关闭 #7、#12、#17、#18、#19 之前，把每条转成实现验收项：

- 时间轴默认 start/end（#7、#12）；
- MCP 渲染截图与 UI 状态（#17）；
- 关键帧范围校验（#18）；
- MI pivot 语义（#19）。

否则会出现“设计写了、issue 关了、代码没做”的空档。

4. **#14** 切分能力缺失：长 PV 调整节奏的基本操作，且新模型已经扫清数据表示障碍，适合尽快补规格。
