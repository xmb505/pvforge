## 重点说明

### 场景、退休、旧迁移整组关闭

#28、#30、#34、#36 是同一轮架构删除的产物：

- 没有场景对象，也没有场景根文件夹，时间轴本身就是无限长；导出范围由选定摄像机决定。
- 没有 retire/归档流程，`_retired` 文件夹和退休场景都不再生成；下线内容用 hidden + locked 表达。
- 旧 .pvproj 不读取、不迁移，打开时直接提示格式废弃。

因此这 4 条不是“以后再做”，而是需求载体已经不存在。关闭时不要再保留“场景 API 补齐”“迁移默认场景范围”之类的待办。

### MCP 权限与父子语义已重写

#26 和 #27 都来自旧 MCP 的“场景解锁 + 默认父级”模型：

- 新模型默认全工程可写，只有删除父级、批量删除、删素材等危险操作要求显式确认；根层实体不再是需要额外解锁的全局对象。
- 改行属于实体自身属性，换父级是单独操作，并且必须显式选择保持世界位置还是保持局部坐标。

关闭这两条时，把“row 不携带父级语义”“根层实体与场景内实体权限一致”写进新 MCP 的工具 schema 与错误信息，不需要保留旧行为。

### D 类关闭前要登记验收

新模型的模型/素材/求解模块正在并行实现，但还没有接入旧 UI 与 MCP。关闭 #20、#22、#27、#31、#32、#33、#35 之前，把每条转成实现验收项：

- #20：视频/音频源帧 = sourceIn + (当前帧 − 实体 start)，预览与导出一致；
- #22：子实体范围必须被所有祖先范围包含；裁剪父级级联裁剪/删除子级；
- #27：entity.update 改 row 不换父级；entity.reparent 必须给 preserveWorld 或 keepLocal；
- #31：entity.trim 删越界关键帧、级联裁剪/删除子级，扩大不恢复；
- #32：音频用实体 start/end + sourceIn 定位，不引入 trimStart/trimEnd 专用字段；
- #33：所有帧号整数校验，关键帧相对实体 start，越界返回允许范围；
- #35：所有写路径复核 locked，包括拖动、裁剪、关键帧、属性与批量操作。

否则会出现“设计写了、issue 关了、代码没做”的空档。

### #21 音画联动被有意取消，但删除提示还应保留

新模型只在导入时把视频拆成视频实体 + WAV 音频实体，之后两者完全独立，没有隐式配对关系。原文要求的“拖动/裁剪视频同步音频”不再成立。

重写方向：

- 标题改成“删除视频时没有提示配对音频”或“导入拆出的音频缺少来源标识”；
- 保留“删除视频时提示还有配对音频，让用户选择一起删或保留”；
- 不再要求移动/裁剪联动；
- 如果产品仍想要联动，需要单独加“链接组”概念，不能靠隐式配对。

### #29 指南要整体重写，不是修补

新模型的 MCP 工具面、权限、帧号语义、素材模型全部换了。原文列的“只读、version 3、scene 不可用、preview.render_frame 不存在”逐条修已经没有意义。

重写方向：

- 按新工具面重写 guide 与 schema；
- 明确默认全工程可写、危险操作需确认、locked 会被拒绝；
- 写清实体/行/私有时间线/关键帧相对实体；
- 只列真实存在且可用的工具，未实现能力标成“未启用”；
- 工程版本号只在 schema 里出现一次，避免和实际保存格式漂移。

### #23、#24、#25 是新模型仍缺的时间轴 UI

这三条与数据模型无关，新模型也没有替它们做决定：

- #23：多选高亮已经有了，但删除、复制、成组仍只作用于最后选中项；Ctrl/Shift 单击也不能追加选择。新模型只说要沿用现有 clip 交互，所以这是纯实现缺口。
- #24：name 是正式字段，MCP 可以改名，但人类界面没有入口；双击名称仍然打关键帧。
- #25：hidden/locked 是正式属性，隐藏实体仍要能在时间轴找到；但行头、右键、属性面板都没有入口，锁定也没有可见标志。

#35 关闭后，把“所有写路径复核 locked”并入 #25 的验收，避免只加了锁按钮但锁不住。
